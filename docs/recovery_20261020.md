## Recurring failures to prevent

- A script existing does not mean backups exist. Require a receipt with repo revision,
  file count, content verification and zero mismatches; open the remote manifest before cleanup.
  The old `hf_backup.py` excludes raw NPZ and step checkpoints: do not use it as complete backup.
- Same-size checkpoint overwrites fooled the mirror. LFS SHA256 / Git blob hashes are required;
  timestamps alone are not integrity. Evaluations record the exact loaded model hash.
- Never mutate a staged backup via hardlinks to live source files. `hf_sync.py` now copies a
  stable snapshot, detects concurrent changes, rejects missing sources and stale same-size files,
  scans git blobs before bundling, and writes a revision-pinned verified receipt.
- Credentials live outside the project in a mode600 credential file. Never archive home,
  `.ssh`, `.netrc`, tokens, command histories or chat transcripts. Bundles need history scanning.
- Old cgroup OOM counted tmpfs plus RSS. Budget aggregate worker memory and shared storage;
  build archives without competing with live checkpoint writes.
- Keep long jobs in named tmux windows; never kill a pane or broad `pkill` to stop a runner.
  Use PID ownership and per-run server identity. Local monitoring tasks do not survive clients.
- Batched serving was not bitwise deterministic. Use batch1 for replay/root causal comparisons;
  include render/contact side effects and controller/history snapshots.
- 5cm arm offsets confused normal tuck with reach. Keep10/15/20cm sensitivity, first onset,
  eligible query counts, distance bins and paired base-episode cluster uncertainty.
- Superseded teacher-forced A/B probes used stale1k best weights; don't revive those conclusions.
  Perturbation verdict remains INCONCLUSIVE; spontaneous drift analysis is exploratory.
- Hardware changes can change numerics. A rebuilt model is requalified, not assumed bit-identical.

`scripts/rebuild_collect_lj.py` is the bounded continuation driver for tmux `lmm:recollect`.
Its state lives in `runtime/rebuild_20261020/collection/`; monitor `events.jsonl`, `stages/*/result.json`,
`receipts/*.json`, `backup.log`, and `logs/rebuild_collection.log`. Existing asset downloads are
adopted unchanged. The driver checks CPU contracts immediately, then waits for all asset/environment
verified receipts, rehashes upstream assets, and runs the existing geometry/NAV/smoke/timing gates.
It uses the persistent HomeRobot data tree directly, so it does not need the legacy tmpfs stager
or its derived TSV manifests. The geometry screener now explicitly sets the requested physical GPU;
its old bare simulator silently defaulted toGPU0. This is a resource-routing fix, not a model change.

Collection has one simulator process, only physicalGPU7. It requires8GiB free VRAM,32GiB available
host/cgroup RAM and100GiB persistent free disk before each simulator launch. Each command records
`/usr/bin/time -v` peak RSS. These are simulation headroom checks, **not evidence that SFT fits**.

The new protocol is recorded in the CPU-preflight stage: existing physical feasibility checks,
three seed-bank replicas, fixed scene-round-robin order with seed1000, base-episode CRC split
(5% SFT validation), OVMM-val never collected for training. First256 geometry-feasible base episodes
are embodiment-screened in64-episode shards. Reserved train-only qualification bases are excluded
from SFT. Forced-left/right/auto manipulation, snapshot replay and a10–20-success pilot gate must
pass before bulk collection. Pilot shards contain at most4 attempted units, bulk shards at most8;
every closed shard (including rejected outcomes) is backed up and remotely hash-verified before
the next starts. Accepted raw episodes additionally check16D state/18D labels, finite values,
10Hz timing, all three camera arrays, lowering consistency and history index mapping.

After the initial pilot, remaining geometry shards are screened and collected incrementally.
The bounded target is at least2000 train and100 SFT-val accepted trajectories, or pool exhaustion.
The final collection index freezes a **new** `lj_recollect_20261020-*` manifest; it is never the
lost original v2 manifest. Counts, rejected attempts and excluded qualification bases are retained.
No training, architecture changes, RL, or automatic repair/retry is included. Later conversion must
still pass all-video decode/drop/alignment checks, exact train-only stats, real-data model interface
and history gates, and measured training memory/resume tests before SFT.

Stage completion requires both a passing result and a verified receipt. If a backup alone failed,
resume backs up completed outputs without rerunning the task. An interrupted/failed stage blocks for
diagnosis and is preserved. Never delete/overwrite it or relaunch a duplicate blindly. Existing
passing stages are adopted; long jobs stay in server tmux across client disconnects.
